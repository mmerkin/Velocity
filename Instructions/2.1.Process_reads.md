# Trim adapters and map/filter reads

## Adapter trimming

It was soon discovered that the standard CGR protocol of using cutadapt to trim the reads resulted in high levels of adapter contamination, perhaps due to the non-standard adaptors of the Velocity data not being recognised. As such, Flora Todd created several files that use the tool [Trimmomatic](https://github.com/usadellab/Trimmomatic) to trim the reads by providing the adapter sequences, which can be found in the folder [Adaptor_trimming](scripts/Adapter_trimming). It is recommended to download this entire folder and run the following commands:

```bash
cd trim_adapters
for i in dir/*R1*; do bash cutadaptors.sh $i; done
```

Briefly, a python script is used to identify the barcode identifier corresponding to the sample id. The adapter sequences are then extracted from the relevant .fa file and trimming is performed whilst also removing the first and last bases with a quality below 20, reads with a length or average quality below 20 and, scanning the read in a sliding window of 4 bases, cutting the read when the average quality falls below 20. Finally, a trimmed file is produced that contains "veladapt.clean". Trimmomatic must be installed.


## Read splitting

Some individuals were sequenced multiple times, so Alex concatenated the reads from each run into a single fastq file. If the status is unknown, information of the sequencing machine and lane number is given in the read tags.

```bash
zcat $READ.fastq.gz | grep "@" | awk -F ":" '{print $1, $2, $3, $4}' | uniq -cd
```

When I was using atlas, I wanted to map the reads from each run separately to add them to different read groups for the quality score recalibration; this also allows for the museum reads to be processed separately as different runs had different numbers of sequencing cycles (read lengths). Reads can be split using [Split_reads.sh](https://github.com/mmerkin/Velocity/tree/New_pipeline/scripts/Split_reads.sh), which will add the code for the flow cell and lane number on the end; these should be used to move the fastq files into separate directories and compressed with bgzip.

Finally, the samples should be renamed in their new directories to remove this identifier e.g.

```bash
for i in *.fastq.gz; do tag=$(echo $i | awk -F "-" '{print $1}'); rename s/^${tag}-// *; done

for i in *.fastq.gz; do tag=$(echo $i | awk -F "_" '{print $2}'); rename s/${tag}// *; done
```

## Read mapping and initial filtering

Trimmed reads can then be mapped to the reference genome using [map_reads.sh](scripts/Processing_reads/map_reads.sh). Firstly, bwa-mem2 is used to perform the mapping and then the indel realignment is performed. However, GATK requires readgroups to be assigned in a certain format, so PICARD is used to add new readgroup information. Subsequently, the filters are filtered to remove unmapped and secondary reads, as well as those with a mapping quality below 20. Finally, ATLAS is used to merge any overlapping reads. 

Most modern variant calling pipelines do not require an indel realignment step, so it is difficult to find a modern tool to perform it. It can still be acheived with GATK3.8, but the commands were
not carried over to GATK4. However, GATK3 requires a local installation, so one must first download the file and activate it in the conda environment GATK38. Alternatively, the correct version
of the package can be downloaded [here](https://anaconda.org/bioconda/gatk)

```bash
wget https://console.cloud.google.com/storage/browser/_details/gatk-software/package-archive/gatk/GenomeAnalysisTK-3.8-1-0-gf15c1c3ef.tar.bz2

tar -xvjf  GenomeAnalysisTK-3.8-1-0-gf15c1c3ef.tar.bz2

cd GenomeAnalysisTK-3.8-1-0-gf15c1c3ef/

gatk-register GenomeAnalysisTK.jar
```

## Merging read groups and removing duplicates

Many samples were sequenced multiple times, so there are multiple bam files for the same individual. As such, the tool bamaddrg is used to merge these bam files together and samtools markdup is used to remove any duplicate reads. However, the removal of duplicates need to occur even if there was only one sequencing run. Also, the museum populations contains a mixture of samples that were sequenced once and those that were sequenced multiple times. As such, there are several versions of the mapping script to account for these differences. 

1) [Mergedup_modern_onerun.sh](scripts/Processing_reads/Mergedup_modern_onerun.sh) takes one input to remove duplicates, so does not perform any merging.
2) [Mergedup_modern_tworuns.sh](scripts/Processing_reads/Mergedup_modern_tworuns.sh) takes two inputs for both merging and duplicate removal, assuming there is an equal number of files in both input directories (as is the case for the modern samples with multiple runs).
3) [Mergedup_museum.sh](scripts/Processing_reads/Mergedup_museum.sh) takes two inputs, assuming there is a main readgroup with more samples than a resequenced readgroup, such as with most museum populations
4) [Mergedup_museum_many_runs.sh](scripts/Processing_reads/Mergedup_museum_many_runs.sh) takes five inputs, assuming the resequenced samples have many readgroups, such as with museum samples that were resequenced across many different lanes.
5) [Mergedup_museum_extra.sh](scripts/Processing_reads/Mergedup_museum_extra.sh) takes three inputs; this is similar to #3, but assumes there is an extra set of samples that were resequenced futher e.g. five museum butterflies from each species.

## Clean up

Finally, any directories containing the duplicate-removed bam files should be moved into a single directory named "bams" and any temporary files should be deleted to save space.
