# Trim adaptors and map/filter reads

## Adaptor trimming

Currently, I am using read files that have had their adaptors trimmed by Flora. Since I may need to refer back to her script, such as if I find that the adaptors were not removed properly, 
I can do so using her script [Remove adaptors.sh](https://github.com/mmerkin/Velocity/blob/main/scripts/Remove_adaptors.sh). Briefly, she created a list of all the adaptor sequences using Carl's library prep spreadsheet and then used
[Trimmomatic](https://github.com/usadellab/Trimmomatic) to remove them, as well as removing bases at the ends of reads with a quality below 20.

## Read splitting

Some individuals were sequenced multiple times, so Alex concatenated the reads from each run into a single fastq file. If the status is unknown, information of the sequencing machine and lane number is given in the read tags.
```bash
zcat $READ.fastq.gz | grep "@" | awk -F ":" '{print $1, $2, $3, $4}' | uniq -cd
```

However, I want to map the reads from each run separately to add them to different read groups for the atlas quality score recalibration. Reads can be split using [Split_reads.sh](https://github.com/mmerkin/Velocity/tree/New_pipeline/scripts/Split_reads.sh), which will add the code for the flow cell and lane number on the end; these should be used to move the fastq files into separate directories.

Finally, the samples should be renamed in their new directories to remove this identifier e.g.

```bash
# perl rename in cpan env
​rename s/$LANE// */*
```

## Read mapping and initial filtering

Once the trimmed reads are placed into a directory for each read group, they can be mapped and filtered using [Filtering_pipeline.sh](https://github.com/mmerkin/Velocity/tree/New_pipeline/scripts/Filtering_pipeline.sh).
Here are parameters used for the grayling as an example:

```bash
datapath=~florat/velocity/hipparchia_semele/modern_data/00_raw_reads_modern/Samples
temp=/pub64/mattm/velocity/D1_Hipparchia_semele/modc_temp
output=/pub64/mattm/velocity/D1_Hipparchia_semele/modc_bams
REF=/pub64/mattm/velocity/D1_Hipparchia_semele/reference/GCA_933228805.2_ilHipSeme1.2_genomic_noW.fa
logfile=process_hs_modc.log
threads=16
remove_temp=true

add_RG=true
RGID=D1modc
RGLB=mod02
```

Most modern variant calling pipelines do not require an indel realignment step, so it is difficult to find a modern tool to perform it. It can still be acheived with GATK3.8, but the commands were
not carried over to GATK4. However, GATK3 requires a local installation, so one must first download the file and activate it in the conda environment GATK38. Alternatively, the correct version
of the package can be downloaded [here](https://anaconda.org/bioconda/gatk)

```bash
wget https://console.cloud.google.com/storage/browser/_details/gatk-software/package-archive/gatk/GenomeAnalysisTK-3.8-1-0-gf15c1c3ef.tar.bz2

tar -xvjf  GenomeAnalysisTK-3.8-1-0-gf15c1c3ef.tar.bz2

cd GenomeAnalysisTK-3.8-1-0-gf15c1c3ef/

gatk-register GenomeAnalysisTK.jar
```

If the website has been taken down, search for a new link on the forums.

Atlas is difficult to install on the CGR cluster due to the presence of multiple versions of some of its dependencies, so it doesn't know which versions to use. Therefore, I created a conda environment
with new versions of these packages to use called PLACEHOLDERTEXT.

Afterwards, one needs to follow the instructions on the [Atlas wiki page](https://atlaswiki.netlify.app/) for installation, which are also given below:

```bash
git clone --depth 1 https://bitbucket.org/WegmannLab/atlas.git
cd atlas
mkdir -p build
cd build
cmake ..
make
```

For ease of use, the command to run atlas can be set as in alias:
```
cd # Return to home directory
nano .bash_aliases
alias atlas='~/apps/atlas/build/atlas'
```
If no aliases have been set before, the if statement in the .bashrc file relating bash_aliases needs to be uncommented out. Note that this may not work in shell scripts, so it is better to provide
the full command

## Merging read groups

In cases where the reads were split before mapping, the bam files can now be merged again as separate read groups using [Merge_museum_readgroups.sh](https://github.com/mmerkin/Velocity/tree/New_pipeline/scripts/Merge_museum_readgroups.sh). Note that the script may need to be modified if files have different names eg 09-HS-01-1900-01_merged.bam will be fine, but HS-01-1900-01_merged.bam will require that the '{print $4 "-" $5}' be changed to '{print $6 "-" $7}'. This script can be further modified to account for additional sequencing runs eg [Merge_museum_extra_readgroups.sh](https://github.com/mmerkin/Velocity/tree/New_pipeline/scripts/Merge_museum_extra_readgroups.sh) and [Merge_modern_sixruns_readgroups.sh](https://github.com/mmerkin/Velocity/tree/New_pipeline/scripts/Merge_modern_sixruns_readgroups.sh).

## Clean up

Some files will still have inconsistent names e.g. lane numbers, so these need to be removed with perl rename (cpan environment). I also rename the samples to remove the word "merged" and then delete any unnecessary files. If necessary, the bam files can be indexed and added to new folders.
```bash
rename s/_merged// */*
rm */*txt
rm */*json
rm */*parameters
parallel -j 10 samtools index {} ::: *.bam
for i in *.bam; do j=$(basename $i .bam); mkdir $j; mv $i* $j; done
```
