# Remove adaptors and map reads

## Adaptor trimming

Currently, I am using read files that have had their adaptors trimmed by Flora. Since I may need to refer back to her script, such as if I find that the adaptors were not removed properly, 
I can do so using her script [Remove adaptors.sh](https://github.com/mmerkin/Velocity/blob/main/scripts/Remove_adaptors.sh). Briefly, she created a list of all the adaptor sequences using Carl's library prep spreadsheet and then used
[Trimmomatic](https://github.com/usadellab/Trimmomatic) to remove them, as well as removing bases at the ends of reads with a quality below 20.

## Read splitting

Some individuals were sequenced multiple times, so Alex concatenated the reads from each run into a single fastq file. However, I want to map the reads from each run separately to add them to different read groups for the atlas quality score recalibration. Reads can be split using [Split_reads.sh](https://github.com/mmerkin/Velocity/tree/New_pipeline/scripts/Split_reads.sh), which will add the code for the flow cell and lane number on the end; these should be used to move the fastq files into separate directories.

## Read mapping and initial filtering

Once the trimmed reads are placed into a directory for each read group, they can be mapped and filtered using [Filtering_pipeline.sh].
Here are parameters used for the grayling as an example:

```bash
datapath=~florat/velocity/hipparchia_semele/modern_data/00_raw_reads_modern/Samples
temp=/pub64/mattm/velocity/D1_Hipparchia_semele/modc_temp
output=/pub64/mattm/velocity/D1_Hipparchia_semele/modc_bams
REF=/pub64/mattm/velocity/D1_Hipparchia_semele/reference/GCA_933228805.2_ilHipSeme1.2_genomic_noW.fa
logfile=process_hs_modc.log
threads=16
remove_temp=true

add_RG=true
RGID=D1modc
RGLB=mod02
```

## Merging read groups

In cases where the reads were split before mapping, the bam files can now be merged again as separate read groups using [Merge_readgroups.sh]
