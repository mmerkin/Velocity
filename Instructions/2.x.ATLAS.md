# Atlas error recalibration

Since the museum samples are subject to post-mortem damage (PMD), they are treated separately from the modern samples. Additionally, this command takes a long time to run, so GNU parallel is used to run it
on multiple samples at the same time rather than the for loops that run one after another. However, this can use a lot of memory, so the parameter --memfree is used to prevent any additional samples from being run when there is less than a specified amount of memory available; if there is less than that value/2 memory left, the most recent task to run will be killed, so retries are set to allow any killed processes to run again when memory becomes available. 

## Updated code for modern samples
```bash
awk -v n=2 'NR <= n {print $1"\t0\t"$2}' $REF.fai > ${SPECIES}_regions.bed

parallel -j 40 --memfree 400G --retries 10 \
~/apps/atlas_rc11/atlas/build/atlas estimateErrors \
--fasta $REF \
--regions $BED \
--minDeltaLL 0.001 \
--logFile {.}_log.txt \
--bam {} ::: */*/*.bam
```
A javascript object notation file will then be produced, ending in _RGInfo.json, containing all of the recalibration parameters; this file should be supplied as an input for any downstream steps.

## Backup recalibration parameter files

Many of the processes in atlas generate one of these _RGInfo.json files, which runs the risk of overwriting the recalibration parameter files if they are not supplied first, meaning that estimateErrors must be run again. To avoid this, it is recommened to backup all recalibration parameter files before running any other atlas commands.

```bash
cp modc_bams/*/*_RGInfo.json recal_backup/modc
```


A vcf file is typically needed to perform population genetic analyses. However, variant callers are likely to be unreliable at such low coverage, so a genotype likelihood file is first produced, which is used to infer the major and minor variants in the population. 


## GLF

ATLAS can be used to call genotype likelihoods in parallel:

```bash
parallel -j 40 --memfree 400G --retries 10 --joblog ${tag}_glf_creation.log \
~/apps/atlas_rc11/atlas/build/atlas GLF --RGInfo {.}_RGInfo.json \
 --bam {} ::: */*/*.bam
```

The output glf.gz file can then be viewed using:

```bash
atlas printGLF --glf $READ.glf.gz | less
```

## majorMinor

Variants can be called based on the entire sample using majorMinor. Note that it is much better to use GLFs when possible, but some tools require a vcf as input. Since the entire sample
is used as an input, this process does not need to be run in parallel.

First a text file needs to be created with the paths to all the glf.gz files on a new line. The sample names can be changed by creating a list of all the names separated by commas and no spaces,
which is stored as a variable "names" here. This assumes that the only directories in the current folder are named after the samples. 

```bash
ls *.glf.gz > ${tag}_glfs.txt
names=$(cat ${tag}_glfs.txt | awk -F "." '{ printf "%s,", $1 }' | sed 's/,$//')

~/apps/atlas_rc11/atlas/build/atlas majorMinor --glf ${tag}_glfs.txt --maxThreads 32 --phredLik --sampleNames $names \
--fasta ../../reference/GCA*.fa --out ${tag}_majmin

tabix ${tag}_majmin.vcf.gz
```


## SFS

A site frequency spectrum can also be constructed from the atlas GLF files for both QC and downstream analysis. First, atlas is used to construct a sample allele frequency (saf), which is converted to a SFS using winSFS.

```bash
~/apps/atlas_rc11/atlas/build/atlas saf --glf $samples --fasta ../../reference/GCA_937612035.1_ilAriArta2.1_genomic.fa
```

Then, REALSFS can be used to make a SFS

```bash
angsd realSFS saf.saf.idx > angsd_output.sfs
angsd realSFS saf2theta saf.saf.idx -sfs angsd_output.sfs -outname C1_extra_theta
angsd thetaStat do_stat C1_extra_theta.thetas.idx -win 10000 -step 1000 -outnames C1_thetas_win10000
```
